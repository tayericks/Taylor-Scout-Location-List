# Taylor Scout — Locked Product Rules (v2.5)

These items are LOCKED. Do not change them unless the owner explicitly says “unlock”.

## Shared visual system
- One Taylor Scout shell across every page and tool.
- 60px navy global header.
- Same Taylor Scout brand treatment, typography, spacing, borders, button shapes and sidebar proportions.
- No floating logos, duplicate logos, decorative blocks or one-off component styles.
- Standard panel border: 1px `#d6e0e7`.
- Standard panel radius: 8px.
- Standard control radius: 7px.
- Shared font stack: Inter / system sans-serif.
- Columns and tables use the same typography and density rules.
- Tool-specific controls belong below or to the right of the shared shell; they do not redesign the shell.

## Locked workflow language
- “Locked” = never change unless explicitly unlocked.
- “Exploring” = preserve the current approved version while alternatives are developed.

## Bible Security Planner
- Security Planner lives inside the Bible; it is not a separate dashboard module.
- Opens from the Security vendor section as a full advanced workspace.
- Default post types: Set, Base Camp, Crew Parking, Catering, Trucks.
- Users can add unlimited custom post types with custom colors and can delete any type.
- Individual post instances keep separate placement, guard count, shift, rate and notes.
- Drag/drop calendar shows prep, hold, shoot and strike in the background.
- Planner shows live guard-shift, guard-hour and estimated-cost totals.
- Security order generation creates concise shift/post text and a street-map view.
- Planner data saves into the Bible record so Bible summary/print output can consume the same data.
- Security is a Waypoint layer concept: the same post records should eventually be spatially editable in Waypoint and toggled as one layer.

## Stability
- Autosave must be quiet and must not reflow/twitch navigation or sidebars.
- Scout Route does not live-refresh the workspace sidebar while the user is working.
- Destructive records require explicit confirmation.
- Existing data keys are preserved unless a migration is explicitly approved.

## Print
- Print is a first-class product surface.
- Approved production templates are to be reproduced precisely and then treated as locked templates.
